示范题（独立示范，不占任何正题）

本示范用 whoami（Windows/Ubuntu/Termux 都有，无需 🌐），只演示 subprocess 的最小完整模板。它不提供其他场景的设计思路或答案；后续任务需要根据各自的题目目标独立完成。

题目：用 subprocess 执行 whoami，把输出拿到 Python 里打印成 "当前用户是：xxx"。

1. 先想什么：任务三步——执行命令（subprocess.run 传命令列表）、拿输出（返回对象里的 .stdout）、处理输出（strip 去掉末尾换行）。

2. 为什么这么写：capture_output=True 把命令输出抓回来（第 11 章）；text=True 让输出是字符串而不是字节串；strip() 去掉输出末尾的换行符——不 strip 的话打印结果会多一个空行。

3. 完整代码：

import subprocess

r = subprocess.run(["whoami"], capture_output=True, text=True)
print("当前用户是：", r.stdout.strip())

4. 怎么验证做对了：输出"当前用户是：你的真实用户名"，与终端直接敲 whoami 的结果一致；把命令换成 ["ls", "-l"] 同样能拿到输出——说明模板是通用的。

场景 1｜批量文件重命名工具

1. 先想什么：先收集普通文件，并在比较扩展名时统一转小写；再生成完整计划。正式执行前一次性检查源文件、目标名重复和目标占用，任何冲突都整体拒绝；执行中异常时回滚已完成项目。

2. 为什么这么写：lower() 使 .jpg 与 .JPG 一致；os.path.isfile() 排除目录；先验证完整计划再执行，避免改到一半才发现冲突。正式操作不使用会覆盖目标的 os.replace。

3. 完整代码（rename_tool.py）：

import argparse
import os


def collect_files(directory, ext):
    ext = ext.lower().lstrip(".")
    result = []
    try:
        names = os.listdir(directory)
    except OSError as exc:
        print(f"读取目录失败：{exc}")
        return result
    for name in names:
        path = os.path.join(directory, name)
        if os.path.isfile(path) and name.lower().endswith("." + ext):
            result.append(name)
    return sorted(result)


def build_plan(files, prefix):
    return [
        (old, f"{prefix}_{number:03d}.{old.rsplit('.', 1)[-1]}")
        for number, old in enumerate(files, 1)
    ]


def validate_plan(directory, plan):
    targets = [new for old, new in plan if old != new]
    if len(targets) != len(set(targets)):
        return False, "生成的目标名重复"
    for old, new in plan:
        source = os.path.join(directory, old)
        target = os.path.join(directory, new)
        if not os.path.isfile(source):
            return False, f"源文件不存在或不是普通文件：{old}"
        if old != new and os.path.exists(target):
            return False, f"目标已存在：{new}"
    return True, ""


def rename_files(directory, plan):
    ok, reason = validate_plan(directory, plan)
    if not ok:
        print(f"拒绝执行：{reason}")
        return False
    completed = []
    try:
        for old, new in plan:
            if old == new:
                continue
            os.rename(os.path.join(directory, old), os.path.join(directory, new))
            completed.append((old, new))
            print(f"[完成] {old} -> {new}")
    except OSError as exc:
        print(f"执行中断：{exc}")
        for old, new in reversed(completed):
            old_path = os.path.join(directory, old)
            new_path = os.path.join(directory, new)
            if os.path.exists(new_path) and not os.path.exists(old_path):
                os.rename(new_path, old_path)
        print("已尝试恢复已完成项目，请重新检查目录")
        return False
    return True


def main():
    parser = argparse.ArgumentParser(description="批量文件重命名工具")
    parser.add_argument("directory", help="要整理的目录路径")
    parser.add_argument("--ext", default="jpg", help="扩展名，不区分大小写")
    parser.add_argument("--prefix", default="photo", help="新文件名前缀")
    parser.add_argument("--dry-run", action="store_true", help="只打印计划，不真正改名")
    args = parser.parse_args()
    if not os.path.isdir(args.directory):
        print(f"目录不存在或不是目录：{args.directory}")
        return 1
    files = collect_files(args.directory, args.ext)
    if not files:
        print("没有找到目标普通文件，或目录不可读")
        return 1
    plan = build_plan(files, args.prefix)
    for old, new in plan:
        print(f"[计划] {old} -> {new}")
    if args.dry_run:
        print(f"共 {len(plan)} 个普通文件（未执行）")
        return 0
    if not rename_files(args.directory, plan):
        return 1
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

4. 怎么验证：先记录测试目录的名称、数量和文件内容。加入 .jpg、.JPG、同名目录、空目录、权限异常等样例；先运行 --dry-run，确认计划后再正式执行。目标冲突、源文件消失或权限异常时，程序应拒绝执行或恢复已完成项目，不能留下部分改名；成功后再次核对文件数量、名称和内容。重复运行时若目标已经存在，应整体拒绝。

    if 71 <= code <= 77:

    if code >= 95:
        return "雷暴"
    return "未知"


def main():
    parser = argparse.ArgumentParser(description="命令行天气查询器")
    parser.add_argument("city", help="城市名")
    args = parser.parse_args()

    if args.city not in CITIES:
        print(f"暂不支持城市：{args.city}，可选：{'、'.join(CITIES)}")
        return

    latitude, longitude = CITIES[args.city]
    url = (
        "https://api.open-meteo.com/v1/forecast?"
        f"latitude={latitude}&longitude={longitude}&current_weather=true"
    )

    try:
        response = requests.get(url, timeout=10)
        if response.status_code != 200:
            print(f"接口返回错误：状态码 {response.status_code}")
            return
        try:
            data = response.json()
        except ValueError as exc:
            print(f"接口数据格式错误：不是有效 JSON（{exc}）")
            return
    except requests.exceptions.RequestException:
        print("网络不通，请检查网络后重试")
        return

    current = data.get("current_weather") if isinstance(data, dict) else None
    if not isinstance(current, dict):
        print("接口数据格式错误：缺少 current_weather 对象")
        return

    required = ("temperature", "weathercode", "windspeed")
    missing = [key for key in required if key not in current]
    if missing:
        print(f"接口数据格式错误：缺少字段 {', '.join(missing)}")
        return

    temperature = current["temperature"]
    code = current["weathercode"]
    windspeed = current["windspeed"]
    valid_number = (int, float)
    if (
        not isinstance(temperature, valid_number)
        or isinstance(temperature, bool)
        or not isinstance(code, int)
        or isinstance(code, bool)
        or not isinstance(windspeed, valid_number)
        or isinstance(windspeed, bool)
    ):
        print("接口数据格式错误：天气字段类型不符合预期")
        return

    print(f"{args.city}当前温度 {temperature}°C，{weather_text(code)}，风速 {windspeed} km/h")


main()

4. 怎么验证：正常接口、未知城市、断网/超时、非 JSON 的 200、缺字段和类型错误都应无 Traceback，并分别给出明确提示。

场景 3｜本机巡检工具雏形

1. 先想什么：三个检查函数 + 报告 + 日志。三个检查函数的完整代码见下方③；它们都按 subprocess 调用模板分别解析输出，但 free -m 输出单位是 MB（纯数字），第二行（索引 1）是 Mem 内存行；check_cpu 只取 uptime 末尾的 load average（负载平均值）。报告 = 三行结果拼起来写入文件；日志 = INFO 记开始/完成。

2. 为什么这么写：内存百分比用 used * 100 // total（整数除法，教科书第 1 章）；负载没有"百分比"，直接报告数值（负载数字在输出末尾 load average: 之后，用 rsplit（从右边切，切到第一次出现的分隔符为止）取最后一段再 strip（去空白）；配合 Linux 第 7 章学过：负载超 CPU 核数才算忙，这里只报数据）；文件名日期用 time.strftime("%Y-%m-%d")（第 5 章学过）；日志用 logging.basicConfig 写文件。范围说明：本版只处理 Ubuntu 正常命令输出（命令存在、返回码 0、输出结构正常）；命令不存在、输出异常等环境问题不在本版范围内，需要时用第 7 章 try/except 自行加强。

3. 完整代码（health_check.py；先 cd ~/lab 再运行，报告和日志都写进练习目录）：

import logging
import subprocess
import time

logging.basicConfig(filename="health_check.log", level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")

def check_disk():  # 磁盘：df -h 根分区使用率
    r = subprocess.run(["df", "-h"], capture_output=True, text=True)
    for line in r.stdout.splitlines():
        parts = line.split()
        if len(parts) >= 6 and parts[5] == "/":
            percent = int(parts[4].strip("%"))
            status = "告警" if percent > 80 else "正常"
            return f"磁盘：使用率 {percent}%，状态：{status}"
    return "磁盘：未找到根分区信息"

def check_memory():  # 内存：free -m 第二行 Mem
    r = subprocess.run(["free", "-m"], capture_output=True, text=True)
    parts = r.stdout.splitlines()[1].split()
    total = int(parts[1])
    used = int(parts[2])
    percent = used * 100 // total
    status = "告警" if percent > 80 else "正常"
    return f"内存：使用率 {percent}%，状态：{status}"

def check_cpu():  # 负载：uptime 末尾的 load average
    r = subprocess.run(["uptime"], capture_output=True, text=True)
    load = r.stdout.strip().rsplit("load average:", 1)[-1].strip()
    return f"负载（1/5/15分钟）：{load}"

def main():
    logging.info("开始巡检")
    report = "\n".join([check_disk(), check_memory(), check_cpu()])
    print(report)
    filename = "health_report_" + time.strftime("%Y-%m-%d") + ".txt"
    with open(filename, "w", encoding="utf-8") as f:
        f.write(report + "\n")
    print("报告已写入", filename)
    logging.info("巡检完成，报告写入 %s", filename)

main()

4. 怎么验证：先 cd ~/lab，记录 health_check.log 当前行数或尾部时间戳；运行后应打印三行检查结果并生成 health_report_今天日期.txt，报告内也是同样三行。只核对本次新增的一条“开始巡检”和一条“巡检完成”，不要固定断言日志总行数；重复运行前重新记录起点。自测阈值：把 percent > 80 临时改成 percent > 0，应输出“告警”，验证后立即改回。最后删除临时报告；若不保留练习日志，可在确认本次记录后删除 health_check.log。Windows 跑 df/free/uptime 会报 FileNotFoundError——正常，本题标了 🌐。

场景 4｜Nginx 日志分析器

1. 先想什么：逐行读取 → 分层校验 IP、引号片段、请求字段和状态码 → 正常行计数 → 坏行记录行号和原因并继续 → 输出报告。

2. 为什么这么写：日志可能有空行、缺引号、短请求行或非数字状态码。解析函数不能只保护引号片段，还要保护请求字段和状态码；坏行跳过并计数，避免一条坏日志拖垮整批分析。

3. 完整代码（log_analyzer.py）：

import argparse


def parse_line(line):
    fields = line.split()
    if not fields:
        return None, "空行"
    ip = fields[0]
    segments = line.split('"')
    if len(segments) < 3:
        return None, "缺少完整引号片段"
    request_parts = segments[1].split()
    if len(request_parts) < 2:
        return None, "请求行字段不完整"
    status_parts = segments[2].split()
    if not status_parts or not status_parts[0].isdigit():
        return None, "状态码缺失或不是数字"
    return (ip, request_parts[1], status_parts[0]), ""


def add_count(data, key):
    data[key] = data.get(key, 0) + 1


def top_items(data, number):
    return sorted(data.items(), key=lambda item: (-item[1], item[0]))[:number]


def main():
    parser = argparse.ArgumentParser(description="Nginx 日志分析器")
    parser.add_argument("logfile", help="日志文件路径")
    args = parser.parse_args()
    ip_count, url404, bad_count = {}, {}, 0
    try:
        source = open(args.logfile, "r", encoding="utf-8")
    except FileNotFoundError:
        print(f"日志文件不存在：{args.logfile}")
        return 1
    except OSError as exc:
        print(f"无法读取日志文件：{exc}")
        return 1
    with source:
        for line_number, raw_line in enumerate(source, 1):
            parsed, reason = parse_line(raw_line.strip())
            if parsed is None:
                bad_count += 1
                print(f"[跳过] 第 {line_number} 行：{reason}")
                continue
            ip, url, status = parsed
            add_count(ip_count, ip)
            if status == "404":
                add_count(url404, url)
    report = ["== 访问量 Top 10 IP =="]
    report.extend(f"{ip}  {count} 次" for ip, count in top_items(ip_count, 10))
    report.append("")
    report.append("== 404 最多的 5 个 URL ==")
    report.extend(f"{url}  {count} 次" for url, count in top_items(url404, 5))
    report.append("")
    report.append(f"坏行：{bad_count}")
    text = "\n".join(report)
    print(text)
    try:
        with open("report.txt", "w", encoding="utf-8") as file:
            file.write(text + "\n")
    except OSError as exc:
        print(f"报告写入失败：{exc}")
        return 1
    print("报告已写入 report.txt")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

4. 怎么验证：在样例中加入空行、短请求行、缺引号、缺状态码和非数字状态码；程序不应崩溃，正常行统计仍应正确，并逐行提示被跳过的原因，报告中的“坏行”数量应与实际一致。正常样例仍应得到 66.249.66.1 为 Top 1（5 次）及 4 个 404 URL。完成后删除 report.txt 和临时日志。

场景 5 ☆｜paramiko 远程巡检雏形（选做 · 可跳过）

1. 先想什么：连接、认证、执行命令和释放连接是四个边界。任何一步失败都要给出可定位信息；每条远程命令都同时读取 stdout、stderr，并检查返回码。

2. 为什么这么写：getpass.getpass 输入密码时不回显；timeout 防止连接无限等待；try/finally 保证连接关闭；recv_exit_status() 区分“有输出但失败”和真正成功。AutoAddPolicy 仅限自己的练习虚拟机，生产环境必须核验主机密钥。

3. 完整代码（remote_check.py）：

安装依赖：Ubuntu 执行 sudo apt install python3-paramiko；未安装时会报 ModuleNotFoundError: No module named 'paramiko'。只连自己的练习虚拟机。

import getpass
import paramiko


def main():
    host = input("Ubuntu IP：").strip()
    user = input("用户名：").strip()
    password = getpass.getpass("密码（不回显）：")
    client = paramiko.SSHClient()
    client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
    try:
        client.connect(host, username=user, password=password,
                       timeout=10, auth_timeout=10, banner_timeout=10)
        for command in ["df -h", "free -m", "uptime"]:
            print("=" * 10, command, "=" * 10)
            stdin, stdout, stderr = client.exec_command(command)
            output = stdout.read().decode("utf-8", errors="replace")
            error = stderr.read().decode("utf-8", errors="replace")
            code = stdout.channel.recv_exit_status()
            print("stdout：", output or "（空）")
            print("stderr：", error or "（空）")
            print("退出码：", code)
            if code != 0:
                print("远程命令失败，请根据 stderr 排查")
    except paramiko.AuthenticationException:
        print("认证失败：用户名或密码错误")
    except (paramiko.SSHException, OSError) as exc:
        print(f"SSH 连接或协议失败：{exc}")
    finally:
        client.close()
        print("SSH 连接已关闭")


main()

4. 怎么验证：在自有 Ubuntu 虚拟机上分别测试 SSH 服务未启动、错误密码、错误端口和远程不存在的命令。四种情况都应友好结束，密码不回显；连接总会在 finally 中关闭。成功命令分别检查 stdout、stderr 和退出码，不能只看 stdout。确认后停止练习连接，不连接生产服务器。没有 Ubuntu SSH 环境可跳过本场景：它不是主线必做，跳过不影响 server-health-check 版本 2 以外的任何进度。
