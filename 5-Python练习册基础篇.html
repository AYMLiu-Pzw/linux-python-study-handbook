示范题 1（独立示范，不占任何正题）

题目：让用户输入 3 行内容，逐行追加写入 notes.txt（先 cd ~/lab 再运行），最后打印"已写入 3 行"。

① 先想什么：三步拼装——input 读一行（第 2 章）、open("a") 追加写（第 6 章）、for 循环 3 次（第 2 章）。写进文件的每一行都要自己补换行符。

② 为什么这么写："a" 模式 = 追加（只往末尾加，不覆盖原内容——第 6 章对比过 w 和 a）；write 不会自动加换行，所以要写 "\n"；range(3) 控制次数。

③ 完整代码：

with open("notes.txt", "a", encoding="utf-8") as f:
    for i in range(3):
        line = input("第 " + str(i+1) + " 行：")
        f.write(line + "\n")
print("已写入 3 行")

④ 怎么验证做对了：跑完 cat notes.txt 能看到你输入的 3 行；再跑一轮（再输 3 行），文件变成 6 行——证明 a 是"追加"不是"覆盖"。

示范题 2（独立示范，不占任何正题）

题目：写一个命令行小工具：--times N（次数）参数，把"你好"打印 N 次，并用 logging 记一条 INFO 日志。

① 先想什么：两个知识点组合——argparse 收参数（第 9 章）、logging 记日志（第 10 章）。流程：解析参数 → 循环打印 → 记一条日志。

② 为什么这么写：type=int 把参数自动转成数字（第 9 章）；logging.basicConfig 配好文件名、级别和格式（第 10 章）；range(args.times) 按次数循环。

③ 完整代码：

import argparse
import logging

logging.basicConfig(filename="hello.log", level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")

parser = argparse.ArgumentParser()
parser.add_argument("--times", type=int, required=True, help="打印次数")
args = parser.parse_args()

for i in range(args.times):
    print("你好")
logging.info("打印了 %s 次", args.times)

④ 怎么验证做对了：python3 hello.py --times 3 打印 3 次"你好"；cat hello.log 有一条 INFO；不传 --times 会报 required 错误；传 --times abc 会报类型错误——四种行为都对，就是真的懂了。

参考答案（书末集中）

先自己做，再看答案。对答案时顺序：① 先想什么 → ② 为什么这么写 → ③ 完整代码 → ④ 怎么验证。跳过前两步直接抄代码，等于白做。

阶段 1

【1-1】

① 先想什么：print 可以接多个参数，分隔符由 sep 控制。

② 为什么这么写：sep 默认是空格，题目要 -，就写 sep="-"；参数按名字、年龄、城市依次排。

③ 完整代码：

print("小明", 19, "杭州", sep="-")

④ 怎么验证：输出 小明-19-杭州；如果把 sep 删掉，输出变成 小明 19 杭州（空格）——对照即懂 sep 的作用。

【1-2】

① 先想什么：只给一个参数 → 就是一个完整的字符串；一个参数根本用不到 sep。

② 为什么这么写：字符串里可以包含空格，直接 print("进度 50%") 就满足要求。题面的"默认值"提示是干扰项：不写 sep 时用的就是默认值——但一个参数时它没有出场机会。

③ 完整代码：

print("进度 50%")

④ 怎么验证：输出 进度 50%。写成 print("进度", "50%") 是两个参数，虽然输出一样，但不满足"一个参数"。

【1-3】

① 先想什么：变量 = 贴标签的盒子；重新赋值 = 把盒子里的东西换掉；type 看类型。

② 为什么这么写：输出一次 → 改值 → 再输出，两次 type 都是 int（60 和 90 都是整数）。

③ 完整代码：

score = 60
print(score)
score = 90
print(score)
print(type(score))

④ 怎么验证：输出 60、90、<class 'int'>；若写成 score = "90"，type 会变成 <class 'str'>。

【1-4】

① 先想什么：三个字面量的"长相"决定类型：不带小数点的是 int、带小数点的是 float、带引号的是 str。

② 为什么这么写：Python 靠字面量形式自动判断类型，不需要声明。

③ 完整代码：

print(type(5))
print(type(5.0))
print(type("5"))

④ 怎么验证：三行输出分别是 <class 'int'>、<class 'float'>、<class 'str'>。一句话总结：数字的长相决定类型——无小数点是 int，有小数点是 float，有引号是 str。

【1-5】

① 先想什么：分割线卡片 = 重复的 = 号 + 文字 + 重复的 = 号；长度用 len。

② 为什么这么写：字符串重复用 *（"=" * 4 就是四个等号），拼接用 +。

③ 完整代码：

line = "=" * 4 + "欢迎" + "=" * 4
print(line)
print("长度:", len(line))

④ 怎么验证：输出 ====欢迎==== 和 长度: 10（4+2+4）；len 数的是字符个数。

【1-6】

① 先想什么：f-string 把变量塞进字符串；控制小数位数用 :.1f。

② 为什么这么写：f"{变量:.1f}" 保留一位小数；名字年龄城市各自放进 {}。

③ 完整代码：

name = "小明"
age = 19
city = "杭州"
pi = 3.14159
print(f"{name}-{age}-{city}")
print(f"{pi:.1f}")

④ 怎么验证：输出 小明-19-杭州、3.1；:.1f 是格式说明（四舍五入到一位）。

【1-7】

② 为什么这么写：/ 真除法得 float、// 整除去尾、% 取余、** 乘方。

③ 完整代码：

print(7 / 2) # 真除法：3.5
print(7 // 2) # 整除：3
print(7 % 2) # 取余：1
print(2 ** 10) # 2的10次方：1024

④ 怎么验证：四个输出分别是 3.5、3、1、1024。

【5-1】

① 先想什么：整段读用 read()；逐行读用 for 循环遍历文件对象。

② 为什么这么写：with open 自动关文件；for line in f 每次读一行；strip() 去掉行尾换行。

③ 完整代码：

先在终端执行建文件（不是 Python 代码）：mkdir -p ~/lab; echo '第一行' > ~/lab/test.txt; echo '第二行' >> ~/lab/test.txt；再 cd ~/lab 跑下面的 Python（本阶段所有文件都放这里，相对路径才找得到）。

④ 怎么验证：整段打印一次、逐行打印一次；不 strip 的话逐行输出间会多空行（行尾换行 + print 自带换行）。

④ 怎么验证：输出 第一次 和 第二次 两行。如果第二次也用 w，最终只剩"第二次"——这就是覆盖与追加的区别。

【5-3】

① 先想什么：dict 存成 JSON 用 json.dump；读回用 json.load；先 import json。

② 为什么这么写：json.dump(对象, 文件) 写入；ensure_ascii=False 让中文正常显示不转码；读回后 load 得到原样的 dict。

【5-4】

① 先想什么：启动时若 JSON 文件存在就读回通讯录——用 os.path.exists（判断文件是否存在，os 模块的常用函数）检查，避免首次运行读不存在的文件报错；退出时把 dict 存进 JSON。

② 为什么这么写：os.path.exists 判断文件在不在，避免首次运行读不存在文件报错；"3"分支里 dump 保存。

③ 完整代码：

import json, os
FILE = "contacts.json"
contacts = {}
if os.path.exists(FILE):
    with open(FILE, "r", encoding="utf-8") as f:
        contacts = json.load(f)
while True:
    cmd = input("1添加 2查询 3保存退出：")
    if cmd == "1":
        name = input("姓名：")
        phone = input("电话：")
        contacts[name] = phone
    elif cmd == "2":
        print(contacts.get(input("查谁："), "查无此人"))
    elif cmd == "3":
        with open(FILE, "w", encoding="utf-8") as f:
            json.dump(contacts, f, ensure_ascii=False)
        print("已保存")
        break

④ 怎么验证：添加一个人 → 选 3 退出 → 再运行程序 → 选 2 能查到刚添加的人（数据跨运行存活）。

【5-5】

① 先想什么：读文件用 open()；文件不存在时它会抛出 FileNotFoundError。要接住这个错误，就用 try（尝试）包住读文件的代码，用 except FileNotFoundError（接住"文件不存在"）处理报错分支。

② 为什么这么写：open() 在文件不存在时必然报错，与其让程序崩溃，不如主动接住并给友好提示。指定异常类型 FileNotFoundError 而不是裸 except，是为了只处理"文件不存在"这一种情况，其他错误仍应暴露出来。

③ 完整代码：

try:
    with open("不存在.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("这个文件不存在，请检查路径")

④ 怎么验证：跑一遍应打印友好提示（而不是红色 Traceback）；把文件名改成一个真实存在的文件再跑，正常打印内容——两种路径都对，说明 try/except 正确。

① 先想什么：在 5-5 基础上加 finally——无论成功失败都执行的收尾代码。

② 为什么这么写：finally 天生是"善后"位置（关文件、发通知），出错不出错都跑。

③ 完整代码：

try:
    with open("不存在.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("这个文件不存在，请检查路径")
finally:
    print("本次读取结束")

④ 怎么验证：文件不存在时输出两行（提示 + 本次读取结束）；换成存在的文件也输出"本次读取结束"——两种走向 finally 都执行。

【5-7】

① 先想什么：行数 = 列表长度 len(lines)；字数 = 每行去掉末尾换行后数一数（len(line.strip())）累加。

② 为什么这么写：readlines 得到行列表；len(line.strip()) 数一行的字符；循环累加出总字数。

③ 完整代码：

with open("test.txt", "r", encoding="utf-8") as f:
    lines = f.readlines()
total = 0
for line in lines:
    total += len(line.strip())
print(f"共{len(lines)}行，{total}个字")

④ 怎么验证：对照文件人工数一遍；报告里的数字与文件一致。

【5-8】

① 先想什么："w" = 清空重写、"a" = 末尾追加；对应 Linux 的重定向符号。

② 为什么这么写：两个模式分别对应 Linux 的覆盖/追加语义，联想记忆。

③ 完整代码：文字作答——"w"（覆盖）打开时先把文件清空再写，对应 Linux 的 >；"a"（追加）从末尾接着写，对应 Linux 的 >>。

④ 怎么验证：口头说清 + 用 5-2 的实验现象佐证。

阶段 6

【6-1】

① 先想什么：requests.get 请求 URL；r.status_code 看状态码；r.json() 解析 JSON。

② 为什么这么写：Open-Meteo 是免注册的公开天气 API；timeout 防止卡死；json() 把响应文本转成 dict。

③ 完整代码：

import requests
r = requests.get("https://api.open-meteo.com/v1/forecast?latitude=30.25&longitude=120.17&current_weather=true", timeout=10)
print(r.status_code)
print(r.json())

④ 怎么验证：输出 200 和一长串 JSON（含 current_weather）；URL 改错会输出 400/404。

【6-2】

① 先想什么：连不上的错都属于 RequestException 一族，用 try/except 接住它输出友好提示。

② 为什么这么写：RequestException 是 requests 所有网络异常的基类，接住它 = 接住"连不上"；用本机未监听的 127.0.0.1:9——连接必然被拒绝，比域名更确定（域名类失败在代理环境下可能被拦成 200 造成无输出）。

③ 完整代码：

import requests
try:
    requests.get("http://127.0.0.1:9", timeout=3)
except requests.exceptions.RequestException:
    print("网络不通")

④ 怎么验证：运行输出"网络不通"且不报 Traceback；把 URL 换成真实网站（如 6-1 用过的接口）则正常返回（无输出即成功）。若你的环境有透明代理把 127.0.0.1:9 也拦成响应，说明网络层被改写，属环境差异——此时在题面注明实际结果即可。

【6-3】

① 先想什么：argparse 三步——建解析器、加参数、解析；用 args.name 取值。

② 为什么这么写：--name 定义命令行参数；required=True 强制必传；args.name 拿值。

③ 完整代码：

import argparse
p = argparse.ArgumentParser()
p.add_argument("--name", required=True)
args = p.parse_args()
print(f"你好，{args.name}")

④ 怎么验证：python3 脚本.py --name 小明 输出"你好，小明"；不带参数运行会被拦截并提示缺少 --name。

【6-4】

① 先想什么：default 给默认值；help 写中文说明（--help 时显示）。

② 为什么这么写：default="世界" 让参数可选；help 让工具自带说明书。

③ 完整代码：

import argparse
p = argparse.ArgumentParser(description="打招呼小工具")
p.add_argument("--name", default="世界", help="你的名字")
args = p.parse_args()
print(f"你好，{args.name}")

④ 怎么验证：不带参数输出"你好，世界"；--name 小明 输出"你好，小明"；--help 显示 description 和"你的名字"。

【6-5】

① 先想什么：logging.basicConfig 配日志到文件；info 记正常、error 记异常。

② 为什么这么写：basicConfig 一次性配好文件名、级别、格式；故意制造 ZeroDivisionError 让 except 分支记一条 error。

③ 完整代码：

import logging
logging.basicConfig(filename="app.log", level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")
logging.info("开始")
try:
    1 / 0
except ZeroDivisionError as e:
    logging.error("出错了：%s", e)
logging.info("结束")

④ 怎么验证：运行无打印；先 rm -f app.log 再运行（logging 默认追加，旧日志行不会消失——每次验证前清掉或换新文件名）。cat app.log 应看到三条本次新增，且顺序对应代码顺序：① INFO 开始 ② ERROR 出错了：division by zero ③ INFO 结束。level=INFO 时 INFO 和 ERROR 都能进文件，缺哪条查哪步。

【6-6】

① 先想什么：改 basicConfig 的 level 为 WARNING，再跑 6-5 的脚本观察 INFO 行消失。

② 为什么这么写：级别过滤机制——只记录"级别 ≥ 设定值"的日志；WARNING 比 INFO 高，INFO 被过滤。

③ 完整代码：把 6-5 的 level=logging.INFO 改成 level=logging.WARNING，其余不变，重跑。

④ 怎么验证：同样先 rm -f app.log 清旧日志再重跑（否则会混着上次的行）。cat app.log 只剩一条 ERROR：INFO 的"开始/结束"都被过滤了——WARNING 级别高于 INFO，INFO 没资格进文件。级别排序：DEBUG < INFO < WARNING < ERROR < CRITICAL。

【6-7】

① 先想什么：subprocess.run 执行系统命令；capture_output 捕获、text 转文本。

② 为什么这么写：命令写成列表 ["df", "-h"]；stdout 里就是命令输出。

③ 完整代码：

import subprocess
r1 = subprocess.run(["df", "-h"], capture_output=True, text=True)
r2 = subprocess.run(["free", "-h"], capture_output=True, text=True)
print(r1.stdout)
print(r2.stdout)

④ 怎么验证：输出和终端里跑 df -h、free -h 一模一样。

【6-8】

① 先想什么：三个知识点组合——argparse 收参数、subprocess 跑命令、logging 记日志。流程：解析参数 → 按参数选命令 → 执行并打印 → 记一条日志。

② 为什么这么写：参数用 choices 限定只接受 disk/mem，传错自动报错；capture_output=True + text=True 捕获输出；日志用 logging.basicConfig 配到文件。

③ 完整代码：

import argparse
import logging
import subprocess

logging.basicConfig(filename="check.log", level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")

parser = argparse.ArgumentParser()
parser.add_argument("--check", choices=["disk", "mem"], required=True, help="查什么：disk 或 mem")
args = parser.parse_args()

cmd = ["df", "-h"] if args.check == "disk" else ["free", "-h"]
r = subprocess.run(cmd, capture_output=True, text=True)
print(r.stdout)
logging.info("检查了 %s", args.check)

④ 怎么验证：--check disk 显示磁盘情况、--check mem 显示内存情况；--check cpu 报"无效选择"；check.log 里每次运行多一条 INFO。四种行为都对即通过。
